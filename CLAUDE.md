## Key Commands
- **Unit Tests:** `./mvnw clean test` (or `./mvnw test -pl ulak-presto-quickwit-connector`)
- **Docker Build & Push:** `./push.sh <version> <platform>` — `<platform>` needs a real platform string (`linux/amd64`); `both` only works as a Jenkins param. `prod=true`: override `prod_ip=192.168.109.203` for OGM.
- **Yucemonitoring:** `kubectl --kubeconfig ~/.kube/yucemonitoring.config -n yucemonitoring`, coordinator `maya-trino-multi-coordinator`. **OGM:** `ssh ulak@192.168.109.203` (master; workers `.204`/`.205`) then `kubectl -n maya3`, coordinator `maya-trino-single-coordinator`. `ulak` is in the `docker` group on all 3 OGM nodes (no sudo needed for `docker`/`kubectl`) but that's daemon access, not filesystem root — see Architecture. Both clusters' Trino container is `trino-coordinator`, not `trino`.
- **Patching a live ConfigMap:** `kubectl patch --type merge --patch-file <json>`, not `get -o yaml | sed | apply -f -` (the `last-applied-configuration` annotation JSON-encodes `data`; `sed` can corrupt its `\n` escapes).

## Architecture & Configuration
- **Multi-tier history routing:** `history-time-threshold-seconds` (also takes an explicit `minutes:seconds` pair) + `history-tiers` (CSV `minutes:thresholdSeconds`) in `quickwit.properties` pick the coarsest rollup index a query's range clears (`HistoryTier`/`HistoryIndexResolver`) — check the live ConfigMap, not this doc. `QwQueryRewriter.java` rewrites raw field names (`tx`) to rollup ones (`tx_max`) whenever `qwIndex` points at a history index, gated on `QwUtil`'s explicit `historyIndexActive` flag, not `historyIndex.equals(qwIndex)`.
- **Custom JSON flattener** (`QwUtil.flattenJsonNode`/`arrangeAggregation`) parses Quickwit responses; verify any fix by running it through Trino live (`kubectl cp` a `.sql` into the trino-coordinator pod, `trino -f`; `trino --execute "$(cat file)"` doesn't survive multi-KB SQL with embedded quotes). `arrangeAggregation()` only propagates a bucket's `key` into its leaf metric when that leaf's value is non-null. Grafana's trino-datasource plugin **base32-encodes** passthrough query bodies — decode `system.runtime.queries.query` (`base64.b32decode`) to see the real query, don't hand-reconstruct from the dashboard JSON.
- **Rhino JS engine** gets native `Math` via scope injection.
- **Redis:** `QueryParameters.connectionId` scopes `RedisCacheWorker` per catalog — see [`ulak-presto-connector-base/CLAUDE.md`](ulak-presto-connector-base/CLAUDE.md). `ConnectorBaseUtil.select()` holds its Jedis connection across the whole downstream fetch, not just cache GET/SET — pool exhaustion traces back here (diagnosed, not fixed).
- **Image registries:** OGM/yucemonitoring's `maya-nexus:35000/...` are different physical registries — push each explicitly, `kubectl set image` by hostname not IP. OGM's `maya-nexus` → `ssb-sdwan-worker1`/192.168.109.204 (`/etc/hosts` on all 3 OGM nodes is the source of truth if it moves again). **No OGM node has real internet or a mirror for bare `docker.io`/`registry.k8s.io`/etc. images** — mirror in via `skopeo copy --dest-tls-verify=false --dest-creds admin:nexus2025! docker://<source> docker://192.168.109.204:35000/<repo>:<tag>` from **outside** the OGM network (e.g. Claude's own session).
- **Quickwit:** metastore is Postgres-backed, independent of `qwdata` — clear orphaned splits via `PUT /api/v1/indexes/{id}/clear`, but the **physical disk isn't reclaimed until the GC sidecar actually runs** (a `clear()` that doesn't move `df` usage isn't evidence the volume is too small — check GC health first). Rejects `"0"` as a datetime lower bound (use `"*"`). Hard-caps `max_hits`/`start_offset` at 10,000.
- **`../qw-rollup-engine`** populates the rollup indexes this connector reads. `tasks.json` (one `intervals: [15, 60]` list per task) is mounted from ConfigMap `qw-rollup-engine-config`, read once at startup (`kubectl patch --type merge` + rollout restart to change, no rebuild needed) — but the Nexus-published Helm chart's own bundled `files/tasks.json` is a **separate, currently stale copy** (missing the `"missing": "N/A"` per-dimension fallback that stops `processor.rs::walk_dimensions` from silently dropping a whole row when a terms-agg bucket comes back empty) — a plain `helm upgrade` will regress it; see `qw-rollup-engine-chart-missing-fix-gap` memory before any chart-based redeploy. Task concurrency/pacing (`max_concurrent_tasks` default 1, `window_pacing_ms`, `idle_sleep_secs`) and file-vs-Redis checkpoint fallback are configurable/logged as of 2026-08-31 (`config.json`; see `src/checkpoint.rs`, `src/task_loop.rs`) — a non-root container + `persistence.type: emptyDir` needs `podSecurityContext.fsGroup` set to the image's uid (10001) or the file-checkpoint fallback silently no-ops.
- **OGM's `ssb-sdwan-master` (192.168.109.203) has repeatedly gone fully unresponsive** under heavy concurrent I/O (2026-08-23/24, 2026-08-28) — deeper root-cause investigation now lives in `machine_ops` (`TODO.md`/`DONE.md`), not here.
