- **Yucemonitoring:** `kubectl --kubeconfig ~/.kube/yucemonitoring.config -n yucemonitoring`, coordinator `maya-trino-multi-coordinator`. **OGM:** `ssh ulak@192.168.109.203` (master; workers `.204`/`.205`) then `kubectl -n maya3`, coordinator `maya-trino-single-coordinator`. `ulak` is in the `docker` group on all 3 OGM nodes (no sudo needed for `docker`/`kubectl`) but that's daemon access, not filesystem root — see Architecture. Both clusters' Trino container is `trino-coordinator`, not `trino`.
- **Patching a live ConfigMap:** `kubectl patch --type merge --patch-file <json>`, not `get -o yaml | sed | apply -f -` (the `last-applied-configuration` annotation JSON-encodes `data`; `sed` can corrupt its `\n` escapes).

## Architecture & Configuration
- **Multi-tier history routing:** `history-time-threshold-seconds` (also takes an explicit `minutes:seconds` pair) + `history-tiers` (CSV `minutes:thresholdSeconds`) in `quickwit.properties` pick the coarsest rollup index a query's range clears (`HistoryTier`/`HistoryIndexResolver`) — check the live ConfigMap, not this doc. `QwQueryRewriter.java` rewrites raw field names (`tx`) to rollup ones (`tx_max`) whenever `qwIndex` points at a history index, gated on `QwUtil`'s explicit `historyIndexActive` flag, not `historyIndex.equals(qwIndex)` (broke once tier escalation could derive a different `qwIndex`).
- **Custom JSON flattener** (`QwUtil.flattenJsonNode`/`arrangeAggregation`) parses Quickwit responses; column names don't match a static trace of the code — verify any fix by running it through Trino live (`kubectl cp` a `.sql` into the trino-coordinator pod, `trino -f`; `trino --execute "$(cat file)"` doesn't survive multi-KB SQL with embedded quotes). `arrangeAggregation()` only propagates a bucket's `key` into its leaf metric when that leaf's value is non-null, so a null metric silently loses its row's identity too, not just its value. Grafana's trino-datasource plugin **base32-encodes** these passthrough query bodies before sending — decode `system.runtime.queries.query` (`base64.b32decode`) to see the real query, don't hand-reconstruct from the dashboard JSON's raw variable text.
- **Rhino JS engine** gets native `Math` via scope injection.
- **Redis:** `QueryParameters.connectionId` scopes `RedisCacheWorker` per catalog — see [`ulak-presto-connector-base/CLAUDE.md`](ulak-presto-connector-base/CLAUDE.md). `ConnectorBaseUtil.select()` holds its Jedis connection across the whole downstream fetch, not just cache GET/SET — pool exhaustion traces back here (diagnosed, not fixed).
- **Image registries:** OGM/yucemonitoring's `maya-nexus:35000/...` are different physical registries — push each explicitly, `kubectl set image` by hostname not IP. OGM's `maya-nexus` → `ssb-sdwan-worker1`/192.168.109.204 (moved from master 2026-08-28; `/etc/hosts` on all 3 OGM nodes is the source of truth if it moves again). **No OGM node has real internet or a mirror for bare `docker.io`/`registry.k8s.io`/etc. images** — a fresh pull of anything uncached fails hard. To mirror a new image in: `skopeo copy --dest-tls-verify=false --dest-creds admin:nexus2025! docker://<source> docker://192.168.109.204:35000/<repo>:<tag>` from **outside** the OGM network (e.g. Claude's own session — it has internet + a direct path to `:35000`); don't hunt for a node with internet, there isn't one.
- **Quickwit:** metastore is Postgres-backed, independent of `qwdata` — clear orphaned splits via `PUT /api/v1/indexes/{id}/clear`, but the **physical disk isn't reclaimed until the GC sidecar actually runs** — this can lag arbitrarily long if the node is unstable, so a `clear()` that doesn't move `df` usage is not evidence the volume is too small, check GC health first. Rejects `"0"` as a datetime lower bound (use `"*"`). Hard-caps `max_hits`/`start_offset` at 10,000 — page past that by splitting on a low-cardinality field (e.g. per-site), not time, if a bucket's docs share one timestamp.
- **`../qw-rollup-engine`** populates the rollup indexes this connector reads. `tasks.json`: one `intervals: [15, 60]` list per task, mounted from ConfigMap `qw-rollup-engine-config` (no image rebuild needed to change it — just `kubectl patch --type merge` + rollout restart, config is read once at startup). Metrics tasks key site as `span_attributes.h`; flow tasks use `span_attributes.v` (no `h` at all) — don't assume `h` is universal. `processor.rs::walk_dimensions` silently drops a row entirely (not just one field) if any dimension's terms-agg bucket list comes back empty for that branch (field absent from those docs) — always give every dimension's terms agg a `"missing": "N/A"` fallback, don't assume "optional field" is safe to leave bare.
- **OGM's `ssb-sdwan-master` (192.168.109.203) has repeatedly gone fully unresponsive** (SSH banner-exchange timeout, all HTTP down, `ping` still works — userspace wedged under heavy concurrent I/O, not a kernel crash; 2026-08-23/24 and 2026-08-28, both resolved via a hypervisor-level VM power-cycle). Host is **VMware**, not Proxmox (confirmed via `systemd-detect-virt`/MAC OUI — correct "Proxmox" if it recurs). No self-service recovery path from inside the cluster (no Proxmox/VMware CLI on any node, no hypervisor UI on the gateway) — needs actual vCenter/ESXi access if SSH won't come back; don't keep retrying SSH/kubectl.
